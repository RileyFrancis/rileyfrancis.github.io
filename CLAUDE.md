# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Riley Francis's personal GitHub Pages site (`rileyfrancis.github.io`), built with Jekyll on top of the `jekyll-theme-minimal` GitHub Pages theme. This repo started as a fork of `pages-themes/minimal`; most of the upstream theme-repo scaffolding (bot configs, gem-publish workflow, release script, Travis CI) has since been stripped out as not applicable to a personal site. `jekyll-theme-minimal.gemspec` remains only because `Gemfile` pulls its dependency list (`jekyll`, `jekyll-seo-tag`, `html-proofer`, `rubocop-github`, `w3c_validators`) from it via `gemspec` — the live site is served by GitHub Pages' own build (which recognizes `theme: jekyll-theme-minimal` as one of its supported themes), so this gemspec only matters for local `bundle install`/CI, not production.

## Commands

```sh
script/bootstrap        # gem install bundler && bundle install
bundle exec jekyll serve   # local dev server at localhost:4000, live rebuild
bundle exec jekyll build   # build to _site/
script/cibuild           # full CI check: build, htmlproofer, rubocop, validate-html, gem build
bundle exec rubocop -D --config .rubocop.yml   # lint Ruby (gemspec, scripts)
bundle exec script/validate-html               # W3C-validate _site/index.html (requires a prior build)
```

There is no JS test suite or bundler — `assets/js/*.js` (and the inline `<script>` in the standalone `asl-demo.html`) are plain scripts loaded directly, no build step.

CI (`.github/workflows/ci.yaml`) runs `script/bootstrap` then `script/cibuild` on every push/PR.

## Architecture

Standard Jekyll layout, minimal customization:

- **Content pages** are top-level `.md` files with YAML front matter (`layout`, `title`) — `index.md` (landing page), `cv.md` (resume/CV, at `/cv/`), `projects.md`, `courses.md`. Page-specific CSS and JS have been extracted out of the Markdown: `projects.md`'s image carousel and `pdf.js`-based PDF viewer load `assets/js/carousel.js` and `assets/js/pdf-viewer.js` via `<script src>` tags (the PDF's URL is passed through a `data-pdf-url` attribute on `#pdf-container` so the Liquid `relative_url` filter still resolves it), with styling in `_sass/` partials. The only third-party inline reference left in the Markdown is the pdf.js CDN `<script src>` (which carries an SRI hash and must load before `pdf-viewer.js`).
- **`_layouts/default.html`** wraps the inner pages (`cv.md`, `projects.md`, `courses.md`); it renders the theme's fixed 280px sidebar `<header>` (name, profile photo, tagline) alongside the content and includes `nav.html`, `footer.html`, and the theme's head partials from `_includes/`. **`_layouts/home.html`** is used only by `index.md`: same head/nav/footer, but no sidebar header — the landing page is a single centered `<main class="home-hero">` column, so it deliberately avoids the `<header>`/`<section>` elements the theme floats and pins. Both layouts wrap their body in `<div class="page-panel">` — the tinted card that separates content from the cubes — which fills `.wrapper`'s content box exactly, leaving the wrapper's own horizontal padding as the transparent gutter the cubes draw into. `.page-panel--split` additionally reserves a 320px column for the pinned sidebar; without it the theme's fixed 280px `<header>` and 700px floated `<section>` overlap, since together they exceed the wrapper's content width.
- **`_sass/jekyll-theme-minimal.scss`** (plus `fonts.scss`, `footer.scss`, `rouge-github.scss`) is the theme stylesheet; `assets/css/style.scss` imports it and then the site-specific partials (`panel.scss` for the tinted `.page-panel` card that both layouts wrap their body in, `home.scss` for the landing page, `resume.scss` for the CV-page resume entries, `carousel.scss` and `pdf-viewer.scss` for the projects page). All page styling compiles into the single `assets/css/style.css`.
- **`_config.yml`** holds site metadata (title, description, GA id, theme name) — this is the source of truth for site-wide variables referenced as `site.*` in templates.
- **`asl-demo.html`** is a standalone, non-Jekyll-templated page (no front matter) — a browser-only ASL fingerspelling classifier demo. It loads TensorFlow.js and MediaPipe Hands from CDNs, runs hand-landmark detection, draws a wireframe-only render of the hand to a hidden canvas, and feeds that into a TF.js `GraphModel` for classification entirely client-side (no server/backend). Its styling lives in `assets/css/asl-demo.css` — a plain, hand-written CSS file (no front matter, so Jekyll copies it verbatim rather than compiling it), linked directly and kept separate from the theme's Sass pipeline to preserve the page's standalone nature. Model weights live in `web_model/` (fp32) and `web_model_fp16/` (fp16) — sharded `.bin` files plus a `model.json` graph definition, exported from a Python-trained model (not built/regenerated by anything in this repo). `asl-demo.html` currently loads `web_model_fp16/model.json`; `web_model/` (fp32) is not yet wired up to any page.
- **`assets/`** holds images, the two research PDFs linked from `cv.md`, fonts, and `css`/`js` subfolders. `assets/css/` has the theme's compiled `style.scss` (which imports the `_sass/` partials) plus the standalone `asl-demo.css`; `assets/js/` has small vanilla-JS helpers (`scale.fix.js`, `smooth_scroll.js`) plus `cubes.js`, the decorative background. `cubes.js` is loaded by both layouts and populates the `.cube-layer` div: it measures the `.wrapper` content box and only draws in the leftover side gutters (drawing nothing at all when they're under ~84px, which is every width below ~1280px), wraps cubes modularly within a viewport-sized band so document height is irrelevant, precomputes its rotation keyframes as SVG path strings, animates via `transform` only, and halts its rAF loop once scrolling settles.

## Working in this repo

- When editing resume/project content, prefer editing the Markdown files directly (`cv.md`, `projects.md`, `courses.md`) — the inline HTML/JS blocks in them are part of the page content, not shared includes.
- Site-wide layout/nav/footer changes go in `_layouts/` and `_includes/`; all visual style — shared or page-specific — belongs in `_sass/` partials imported from `assets/css/style.scss`, not inline in the Markdown.
- `web_model*/` binary shards are committed model artifacts — don't regenerate or hand-edit them; if the model changes, the whole directory should be replaced as a unit.
