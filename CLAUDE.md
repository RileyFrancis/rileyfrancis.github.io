# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Riley Francis's personal GitHub Pages site (`rileyfrancis.github.io`), built with Jekyll on top of the `jekyll-theme-minimal` GitHub Pages theme. This repo started as a fork of `pages-themes/minimal`; most of the upstream theme-repo scaffolding (bot configs, gem-publish workflow, release script, Travis CI) has since been stripped out as not applicable to a personal site. `jekyll-theme-minimal.gemspec` remains only because `Gemfile` pulls its dependency list (`jekyll`, `jekyll-seo-tag`, `html-proofer`, `rubocop-github`, `w3c_validators`) from it via `gemspec` — the live site is served by GitHub Pages' own build (which recognizes `theme: jekyll-theme-minimal` as one of its supported themes), so this gemspec only matters for local `bundle install`/CI, not production.

## Commands

```sh
script/bootstrap        # gem install bundler && bundle install
bundle exec jekyll serve   # local dev server at localhost:4000, live rebuild
bundle exec jekyll build   # build to _site/
script/cibuild           # full CI check: build, htmlproofer, rubocop, validate-html, gem build
bundle exec rubocop -D --config .rubocop.yml   # lint Ruby (gemspec, scripts)
bundle exec script/validate-html               # W3C-validate _site/index.html (requires a prior build)
```

There is no JS test suite or bundler — `assets/js/*.js` (and the inline `<script>` in the standalone `asl-demo.html`) are plain scripts loaded directly, no build step.

CI (`.github/workflows/ci.yaml`) runs `script/bootstrap` then `script/cibuild` on every push/PR.

## Architecture

Standard Jekyll layout, minimal customization:

- **Content pages** are top-level `.md` files with YAML front matter (`layout`, `title`) — `index.md` (resume/CV, home page), `projects.md`, `courses.md`. Page-specific CSS and JS have been extracted out of the Markdown: `projects.md`'s image carousel and `pdf.js`-based PDF viewer load `assets/js/carousel.js` and `assets/js/pdf-viewer.js` via `<script src>` tags (the PDF's URL is passed through a `data-pdf-url` attribute on `#pdf-container` so the Liquid `relative_url` filter still resolves it), with styling in `_sass/` partials. The only third-party inline reference left in the Markdown is the pdf.js CDN `<script src>` (which carries an SRI hash and must load before `pdf-viewer.js`).
- **`_layouts/default.html`** wraps all pages; includes `nav.html`, `footer.html`, and the theme's head partials from `_includes/`.
- **`_sass/jekyll-theme-minimal.scss`** (plus `fonts.scss`, `footer.scss`, `rouge-github.scss`) is the theme stylesheet; `assets/css/style.scss` imports it and then the site-specific partials (`resume.scss` for the home-page resume entries, `carousel.scss` and `pdf-viewer.scss` for the projects page). All page styling compiles into the single `assets/css/style.css`.
- **`_config.yml`** holds site metadata (title, description, GA id, theme name) — this is the source of truth for site-wide variables referenced as `site.*` in templates.
- **`asl-demo.html`** is a standalone, non-Jekyll-templated page (no front matter) — a browser-only ASL fingerspelling classifier demo. It loads TensorFlow.js and MediaPipe Hands from CDNs, runs hand-landmark detection, draws a wireframe-only render of the hand to a hidden canvas, and feeds that into a TF.js `GraphModel` for classification entirely client-side (no server/backend). Its styling lives in `assets/css/asl-demo.css` — a plain, hand-written CSS file (no front matter, so Jekyll copies it verbatim rather than compiling it), linked directly and kept separate from the theme's Sass pipeline to preserve the page's standalone nature. Model weights live in `web_model/` (fp32) and `web_model_fp16/` (fp16) — sharded `.bin` files plus a `model.json` graph definition, exported from a Python-trained model (not built/regenerated by anything in this repo). `asl-demo.html` currently loads `web_model_fp16/model.json`; `web_model/` (fp32) is not yet wired up to any page.
- **`assets/`** holds images, the two research PDFs linked from `index.md`, fonts, and `css`/`js` subfolders. `assets/css/` has the theme's compiled `style.scss` (which imports the `_sass/` partials) plus the standalone `asl-demo.css`; `assets/js/` has small vanilla-JS helpers (`cubes.js`, `scale.fix.js`, `smooth_scroll.js`).

## Working in this repo

- When editing resume/project content, prefer editing the Markdown files directly (`index.md`, `projects.md`, `courses.md`) — the inline HTML/JS blocks in them are part of the page content, not shared includes.
- Site-wide layout/nav/footer changes go in `_layouts/` and `_includes/`; all visual style — shared or page-specific — belongs in `_sass/` partials imported from `assets/css/style.scss`, not inline in the Markdown.
- `web_model*/` binary shards are committed model artifacts — don't regenerate or hand-edit them; if the model changes, the whole directory should be replaced as a unit.
